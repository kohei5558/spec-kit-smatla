# Feature Specification: 問題を起動時に最新のセットに合わせる

**Feature Branch**: `011-problem-sync`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月10日
**Status**: Draft
**Input**: User description: "公開後に問題を追加・更新できるようにする"

## 背景

問題は DB が空のときだけ投入される（`DatabaseInitializer`）。そのため、問題の作り方を変えても（008 の難易度表、009 のあまりのあるわり算）既存の DB には反映されない。実際に、008 より前に作った PostgreSQL の DB には古い問題（700問、「10 × 10 = ?」が難易度6など）が残り、あまりのあるわり算は1問もなかった。

開発中は DB を作り直せば済むが、DB を作り直すと学習記録・アカウント・ポイント・景品などもすべて消えるため、公開後の本番では使えない。

## Clarifications

### Session 2026-10-10

- Q: いつ反映するか？ → A: アプリの起動時に自動で反映する（新しい版をデプロイするだけで反映される）
- Q: 最新のセットにない古い問題は？ → A: 出題しないが残す（学習記録が問題文・正解を問題の側に持っているため。記録・正答率・ポイントとの食い違いを起こさない）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 新しい問題が既存の DB にも反映される (Priority: P1)

運営者が問題の作り方を変えた版をデプロイすると、起動時に足りない問題が追加される。DB を作り直す必要はなく、学習記録などはそのまま残る。

**Why this priority**: これがないと、公開後に単元を足したり問題を直したりできない。

**Independent Test**: 古い問題だけが入った DB で起動し、最新のセットの問題が追加され、既存の学習記録が残っていることを確認する。

**Acceptance Scenarios**:

1. **Given** 008 より前の問題（700問）だけが入った DB、**When** 新しい版で起動する、**Then** 最新のセット（あまりのあるわり算を含む）の問題がすべて出題できる状態になる
2. **Given** 子供の学習記録がある DB、**When** 新しい版で起動する、**Then** 学習記録・ポイント・アカウントは変わらない
3. **Given** 空の DB、**When** 起動する、**Then** 最新のセットの問題がすべて入る（今までと同じ）
4. **Given** 最新のセットと同じ問題が入った DB、**When** もう一度起動する、**Then** 何も変わらない（問題の ID も変わらない）

---

### User Story 2 - 最新のセットにない問題は出題しない (Priority: P1)

最新のセットにない古い問題は「使わない」状態になり、問題・デイリーチャレンジに出なくなる。学習記録の一覧では今までどおり表示される。

**Why this priority**: 古い問題が残って出題されると、難易度表と合わない問題（例: 難易度6の「10 × 10」）が出続ける。

**Independent Test**: 古い問題に学習記録がある DB で起動し、その問題が出題されないこと、学習記録の一覧には表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 最新のセットにない問題、**When** 起動する、**Then** その問題は「使わない」状態になる
2. **Given** 「使わない」問題、**When** 問題を取得する・デイリーチャレンジが作られる、**Then** その問題は選ばれない
3. **Given** 「使わない」問題の学習記録、**When** 学習結果を見る、**Then** 問題文・答え・正解が今までどおり表示され、正答率にも入る
4. **Given** 「使わない」問題が最新のセットに戻った、**When** 起動する、**Then** また出題されるようになる（同じ問題 ID のまま）

### Edge Cases

- 問題が同じかどうかは「計算の種類・難易度・問題文」で判断する。同じ問題文でも難易度が変わったら別の問題として扱う（古い方は使わない状態、新しい方を追加）
- 同じ問題で正解（あまりを含む）が違う場合は、正解を最新のセットに合わせる（作り方の誤りを直したとき）
- 起動前に画面に出ていた問題が「使わない」になっても、その問題への回答は受け付ける（答えの判定はできるため）
- 今日のデイリーチャレンジが「使わない」問題でも、その日はそのまま使う（翌日から新しい問題になる）
- レベル（1〜10 の必要正解数・難易度の範囲）は今回の対象外（今までどおり空のときだけ投入）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 起動時に、DB の問題を `ProblemGenerator` の最新のセットに合わせなければならない（足りない問題を追加、最新のセットにない問題を使わない状態にする、使わない状態の問題がセットに戻ったら使う状態に戻す）
- **FR-002**: 問題は削除してはならない（学習記録・デイリーチャレンジが参照しているため）
- **FR-003**: 問題の取得とデイリーチャレンジの問題選びは、使う状態の問題だけから選ばなければならない
- **FR-004**: 合わせる処理は、変化がなければ DB を書き換えてはならない（何度起動しても同じ結果）
- **FR-005**: 起動時のログに、追加・使わない状態にした・戻した問題の数を出さなければならない

### Key Entities

- **Problem**: `IsActive`（bool、出題に使うか）を追加。既存の問題はマイグレーションで使う状態（true）にし、起動時の処理で最新のセットに合わせる

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: DB を作り直さずに、新しい版の問題が出題されるようになる
- **SC-002**: 古い問題の学習記録は1件も消えない
- **SC-003**: 最新のセットにない問題は出題されないことを自動テストで確認できる
