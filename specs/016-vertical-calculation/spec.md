# Feature Specification: ひっ算の見た目

**Feature Branch**: `feature/016-vertical-calculation`
**Created**: 2026年10月26日
**Status**: Implemented
**Input**: User description: "けたの多い計算を、学校と同じひっ算（たて書き）の形で見せる"

## 背景

問題は「345 + 278 = ?」のように横書きで、答えの欄は問題の下に1つ。小3で習う3〜4けたのたし算・ひき算、2〜3けた×1けたのかけ算は、学校ではひっ算（たて書き）で解く。画面でも同じ形にして、紙と同じ感覚で解けるようにする。

## Clarifications

### Session 2026-10-26

- Q: どの計算をひっ算の形にする？ → A: たし算・ひき算・かけ算・わり算（あまりのあるわり算も、わり算の形で）
- Q: どんなときに？ → A: けたが多いときだけ。たし算・ひき算・かけ算は、どちらかの数が2けた以上のとき。わり算は、九九の逆（56÷7 など）は暗算で解くため、**商が2けた以上**のとき（72÷3 など）
- Q: 答えの入れ方は？ → A: 線の下（わり算は厂の上の商の位置）に答えの欄1つ。1けたずつのマスにはしない
- Q: くり上がり・くり下がりのメモ欄は？ → A: いらない

## 見た目

```
たし算・ひき算・かけ算        わり算（あまりあり）
     3 4 5                       [ 商 ]
  +  2 7 8                    ┌──────
  ────────                  3 ) 7 4
   [ 答え ]                  あまり [  ]
```

- 数字は右（一の位）でそろえる
- 答えの判定・API・問題の作り方は変えない（画面の見た目だけ）
- 1けたどうし（3 + 5、6 × 7）と、商が1けたのわり算（56 ÷ 7）は今までどおり横書き

## User Scenarios & Testing _(mandatory)_

### User Story 1 - けたの多い問題をひっ算の形で解く (Priority: P1)

**Independent Test**: 子供でログインし、3けたのたし算・2けた×1けたのかけ算・商が2けたのわり算を出して、たて書きで表示され、線の下（商の位置）の欄に答えて正しく判定されることを確認する。

**Acceptance Scenarios**:

1. **Given** 「345 + 278 = ?」、**When** 問題画面を開く、**Then** 345 の下に「+ 278」が右でそろって並び、線の下に答えの欄がある
2. **Given** 「72 ÷ 3 = ?」、**When** 問題画面を開く、**Then** 厂の形で、商の欄が上にある
3. **Given** 「75 ÷ 4 = ?」（あまりあり）、**When** 問題画面を開く、**Then** 厂の形で、商の欄が上、「あまり」の欄が下にある
4. **Given** 「6 × 7 = ?」や「56 ÷ 7 = ?」、**When** 問題画面を開く、**Then** 今までどおり横書き
5. **Given** ひっ算の形の問題、**When** 答えを入れて「答える」を押す、**Then** 今までどおり判定される（Enter でも答えられる）

### Edge Cases

- 時こく・長さ重さかさ（文章の問題）は対象外
- スマホの幅でも、数字の位がずれない

## Requirements _(mandatory)_

- **FR-001**: たし算・ひき算・かけ算で、どちらかの数が2けた以上の問題は、ひっ算（たて書き）の形で表示しなければならない
- **FR-002**: わり算・あまりのあるわり算で、商が2けた以上の問題は、厂の形で表示しなければならない
- **FR-003**: 答えの欄は線の下（わり算は商の位置、あまりは下）に置かなければならない
- **FR-004**: 判定・API・問題の作り方は変えてはならない

## Success Criteria _(mandatory)_

- **SC-001**: けたの多い問題が、学校のひっ算と同じ並びで表示される
- **SC-002**: 既存の判定・学習記録は変わらない（既存のテストがそのまま通る）
