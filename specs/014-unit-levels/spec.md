# Feature Specification: 単元（計算の種類）ごとのレベル

**Feature Branch**: `feature/014-unit-levels`
**Created**: 2026年10月26日
**Status**: Implemented
**Input**: User description: "時こくと時間（013）などの新しい単元を、その単元のやさしい問題から始められるようにする。単元ごとに得意・苦手が分かるようにする"

> 013（時こくと時間）より先に実装する。013 はこの仕組みの上に作る。

## 背景

子供のレベルは1人に1つ（`Student.CurrentLevelId` と、レベルアップ用の連続正解数 `Student.CorrectAnswers`）で、どの計算の種類でも同じレベルの難易度から出題される。

- 小3はレベル5（難易度5〜6）から始まるため、新しい単元（013 の時こくと時間など）を足しても、その単元の基本（難易度1〜4）がほとんど出ない
- たし算は得意でもわり算は苦手、という違いがレベルに表れない。たし算で正解を重ねると、わり算もむずかしくなる
- 1つの種類で間違えると、ほかの種類で積み上げた連続正解数も0に戻る

## Clarifications

### Session 2026-10-26

- Q: 単元の分け方は？ → A: 計算の種類ごと（たし算・ひき算・かけ算・わり算・あまりのあるわり算、今後の時こくと時間なども1つずつ）
- Q: 新しい単元はどのレベルから始めるか？ → A: レベル1から。四則とあまりのあるわり算は、今までどおり学年で決め（008）、今のレベルを引き継ぐ
- Q: 子供のホーム画面での見せ方は？ → A: 計算の種類を選ぶボタンに、それぞれのレベルを添える
- Q: 保護者の「子供の詳細」画面にも出すか？ → A: 出す（種類ごとのレベルと正答率）

## 決めたこと（Clarifications 以外）

- **今のレベルの引き継ぎ**: 既存の子供は、今のレベルと連続正解数を、既存の5種類すべてにそのまま写す（今までと同じ問題が出続ける）
- **レベルアップの決まり**: 今までと同じ（そのレベルの必要な連続正解数に達したら1つ上がる。間違えたら連続正解数は0）。ただし数えるのは**その種類の中だけ**
- **「すべて」を選んだとき**: まず種類を選び、その種類のレベルに合った難易度から出す。答えたら、その問題の種類のレベルが変わる
- **デイリーチャレンジ**（010）: 対象の4種類（たし算・ひき算・かけ算・わり算）から1つ選び、その種類のレベルの最大難易度から作る
- **学年を上げたとき**（008）: 学年で決まるレベルより低い種類だけ、そのレベルまで上げる（新しい単元は対象外）
- **画面の大きなレベル表示**（ホームの「レベル ○」、問題画面のレベル・連続正解数）: ホームは**いちばん高いレベル**、問題画面は**今の問題の種類**のレベルと連続正解数にする。ホームの「連続正解」の枠は種類ごとに分かれて1つに決まらないため外し、代わりに種類のボタンに「あと○問でレベルアップ」を出す
- **レベルアップの演出**（問題画面）: 「たし算が レベル7 になったよ！」のように種類の名前を入れる

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 種類ごとにレベルが上がる (Priority: P1)

子供が問題を解くと、その問題の種類のレベルだけが上がり下がりの判定に使われる。ほかの種類のレベルと連続正解数は変わらない。

**Why this priority**: 本機能の中心。

**Independent Test**: たし算を必要数だけ連続で正解し、たし算だけレベルが上がり、わり算のレベルと連続正解数が変わらないことを確認する。

**Acceptance Scenarios**:

1. **Given** たし算・わり算ともレベル5、**When** たし算を15問連続で正解する、**Then** たし算はレベル6、わり算はレベル5のまま
2. **Given** たし算の連続正解数が10、**When** わり算を間違える、**Then** たし算の連続正解数は10のまま、わり算の連続正解数は0
3. **Given** たし算がレベル7・わり算がレベル5、**When** それぞれの種類を選んで問題を出す、**Then** たし算はレベル7、わり算はレベル5の難易度から出る
4. **Given** 「すべて」を選んだ、**When** 問題を解く、**Then** それぞれの問題は、その種類のレベルの難易度から出て、答えるとその種類のレベルが変わる

---

### User Story 2 - 新しい子供・既存の子供のレベル (Priority: P1)

新しく作った子供は、四則とあまりのあるわり算が学年で決まるレベル、それ以外（今後の新しい単元）がレベル1から始まる。既存の子供は今のレベルを引き継ぐ。

**Why this priority**: これがないと、既存の子供のレベルが失われるか、新しい単元が基本から始まらない。

**Independent Test**: 小3の子供を作って種類ごとのレベルを確認する。既存の子供のデータで移行後のレベルを確認する。

**Acceptance Scenarios**:

1. **Given** 保護者が小3の子供を作る、**When** 種類ごとのレベルを見る、**Then** 四則とあまりのあるわり算はレベル5
2. **Given** レベル7・連続正解数3の既存の子供、**When** 移行したあと、**Then** 既存の5種類すべてがレベル7・連続正解数3
3. **Given** 新しい種類が追加された（013 など）、**When** その種類の問題を初めて出す、**Then** その種類はレベル1から始まる
4. **Given** 小2の子供（四則はレベル3）を小3に変更する、**When** 種類ごとのレベルを見る、**Then** レベル5より低い四則とあまりのあるわり算はレベル5になり、それ以上の種類は変わらない

---

### User Story 3 - 子供と保護者が種類ごとのレベルを見る (Priority: P2)

子供のホーム画面の種類のボタンに、それぞれのレベルが出る。保護者の「子供の詳細」に、種類ごとのレベルと正答率が出る。

**Why this priority**: 得意・苦手を見えるようにする。US1 がないと意味がないため P2。

**Independent Test**: 種類ごとにレベルが違う子供で、ホーム画面と保護者の子供の詳細を開く。

**Acceptance Scenarios**:

1. **Given** たし算レベル7・わり算レベル5の子供、**When** ホーム画面を開く、**Then** 種類のボタンに「レベル7」「レベル5」のように出る。大きなレベル表示は「レベル 7」（いちばん高いレベル）
2. **Given** たし算の問題を解いている、**When** 問題画面を見る、**Then** レベルと連続正解数はたし算のもの
3. **Given** たし算がレベルアップした、**When** 演出を見る、**Then** 「たし算が レベル8 になったよ！」と出る
4. **Given** 保護者が子供の詳細を開く、**When** 学習統計を見る、**Then** 種類ごとのレベルと正答率の表が出る

### Edge Cases

- レベル10（最高）の種類で正解を重ねても、それ以上は上がらない（今までどおり）
- デイリーチャレンジは連続正解数・レベルを変えない（今までどおり）
- まだ一度も解いていない種類も、ボタンと保護者の画面にレベルが出る（四則は学年のレベル、新しい単元はレベル1）
- 子供を削除したら、種類ごとのレベルも消える
- 種類ごとのレベルの行が無い（新しい種類を足した直後など）ときは、その場で始めるレベルの行を作る

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 学習者は、計算の種類ごとにレベルとレベルアップ用の連続正解数を持たなければならない
- **FR-002**: 問題を出すときの難易度の範囲は、その問題の種類のレベルで決めなければならない（「すべて」のときも、選んだ種類のレベル）
- **FR-003**: 回答の判定後、連続正解数とレベルアップは、その問題の種類のものだけを変えなければならない
- **FR-004**: 子供を作るとき、四則とあまりのあるわり算は学年で決まるレベル（008 の `GradeStartLevel`）、それ以外の種類はレベル1で始めなければならない
- **FR-005**: 既存の学習者は、移行時に今のレベルと連続正解数を、既存の5種類すべてに写さなければならない
- **FR-006**: 学年を上げたとき、四則とあまりのあるわり算のうち、学年で決まるレベルより低いものだけを上げなければならない
- **FR-007**: デイリーチャレンジは、対象の種類から1つ選び、その種類のレベルの最大難易度から作らなければならない
- **FR-008**: 学習者の情報を返す API は、種類ごとのレベルと連続正解数を返さなければならない。回答結果のレベルアップ情報には、どの種類が上がったかを含めなければならない
- **FR-009**: 子供のホーム画面は種類のボタンにレベルを、問題画面は今の問題の種類のレベルと連続正解数を表示しなければならない
- **FR-010**: 保護者の子供の詳細は、種類ごとのレベルと正答率を表示しなければならない

### Key Entities

- **StudentLevel**（新規）: 学習者・計算の種類・レベル・連続正解数。学習者と種類の組み合わせで1行
- **Student**: `CurrentLevelId` と `CorrectAnswers` は、種類ごとのレベルに置き換える（扱いは plan.md）

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: ある種類で正解・不正解を重ねても、ほかの種類のレベルと連続正解数は変わらない（自動テストで確認）
- **SC-002**: 既存の子供は、移行の前後で同じ難易度の問題が出る（自動テストで確認）
- **SC-003**: 新しい種類は、学年に関係なくレベル1（難易度1〜2）から出題される
- **SC-004**: 子供と保護者が、種類ごとのレベルを画面で確認できる
