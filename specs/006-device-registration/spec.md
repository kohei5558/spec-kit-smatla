# Feature Specification: 子供用端末の登録

**Feature Branch**: `006-device-registration`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月8日
**Status**: Draft
**Input**: User description: "子供ログイン画面で全家庭の子供の名前が認証なしに見えてしまう問題を、端末登録方式で解消する。保護者が『この端末を子供用に登録する』ボタンを押したときだけ登録する"

## 背景

現在の子供ログイン画面は、認証不要の API（`GET /api/child-accounts/public`）から**全家庭**の有効な子供アカウント（名前・学年・アバター）を取得して表示している。インターネットに公開すると、第三者が子供の名前と学年を閲覧できる。これは constitution v2.0.0 の「子供の識別情報は保護者の認証を経ない限り公開しない」に違反する。

## Clarifications

### Session 2026-10-08

- Q: 子供が使う端末をどう特定するか？ → A: 保護者がその端末でログインし、「この端末を子供用に登録する」ボタンを押した端末だけを子供用として扱う（保護者ログインだけでは登録しない）
- Q: 登録の有効期限は？ → A: 期限なし。保護者が解除するまで有効
- Q: 子供の PIN ログインに端末登録を必須にするか？ → A: 必須にする（未登録端末からの PIN 総当たりを防ぐ）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 保護者が端末を子供用に登録する (Priority: P1)

保護者が子供に使わせる端末（自宅のタブレットなど）でログインし、子供アカウント管理画面の「この端末を子供用に登録する」ボタンを押す。端末に名前（例：「リビングのタブレット」）を付けて登録すると、以降その端末の子供ログイン画面に自分の家庭の子供だけが表示される。

**Why this priority**: 登録がなければ子供はログインできない。本機能の基盤。

**Independent Test**: 保護者でログインして端末を登録し、ログアウト後に子供ログイン画面を開いて自分の家庭の子供だけが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 保護者が子供アカウント管理画面を開いていて、この端末が未登録の状態で、**When** 画面を表示する、**Then** 「この端末を子供用に登録する」ボタンが表示される
2. **Given** 上記の状態で、**When** ボタンを押し、端末名「リビングのタブレット」を入力して登録する、**Then** 「この端末を子供用に登録しました」と表示され、ボタンの代わりに「この端末は子供用に登録済みです」と表示される
3. **Given** 端末が登録済みの状態で、**When** 保護者がログアウトして子供ログイン画面を開く、**Then** その保護者の子供（有効なアカウントのみ）のカードだけが表示される
4. **Given** 端末が登録済みで子供ログイン画面が表示されている状態で、**When** 子供が自分のカードを選び正しい PIN を入力する、**Then** 子供用ホーム画面が表示される
5. **Given** 保護者が端末を登録しないまま保護者としてログインし、ログアウトした状態で、**When** 子供ログイン画面を開く、**Then** 子供の一覧は表示されない（保護者ログインだけでは登録されない）

---

### User Story 2 - 未登録の端末では子供の情報が見えない (Priority: P1)

登録されていない端末で子供ログイン画面を開いても、子供の名前・学年・アバターは一切表示されず、保護者に登録を促す案内だけが表示される。

**Why this priority**: 本機能の目的そのもの（子供の個人情報保護）。US1 と同時に必要。

**Independent Test**: 未登録の端末（または端末トークンを削除したブラウザ）で子供ログイン画面と API を呼び、子供の情報が返らないことを確認する。

**Acceptance Scenarios**:

1. **Given** 未登録の端末で、**When** 子供ログイン画面を開く、**Then** 「この端末はまだ子供用に登録されていません。おうちの人に登録してもらってね」という案内と保護者ログインへのリンクだけが表示され、子供の一覧は表示されない
2. **Given** 端末トークンを持たないクライアントが、**When** 子供一覧の API を呼ぶ、**Then** 401 が返り、子供の情報は含まれない
3. **Given** 端末トークンを持たないクライアントが、**When** 子供の ID と PIN で子供ログイン API を呼ぶ、**Then** 401 が返り、PIN の失敗回数は加算されない
4. **Given** 家庭 A で登録した端末のトークンで、**When** 家庭 B の子供の ID で子供ログイン API を呼ぶ、**Then** 401 が返る
5. **Given** 認証不要だった `GET /api/child-accounts/public` を、**When** 呼ぶ、**Then** 404 が返る（エンドポイント廃止）

---

### User Story 3 - 保護者が登録済みの端末を確認・解除する (Priority: P2)

保護者は子供アカウント管理画面で、登録済みの端末の一覧（端末名・登録日・最終利用日）を見て、不要な端末（なくした・譲った端末など）の登録を解除できる。

**Why this priority**: 端末の紛失時に子供の情報を守るために必要だが、US1・US2 がなくても単独では意味がないため P2。

**Independent Test**: 2台の端末を登録し、片方を解除した後、その端末の子供ログイン画面に子供の一覧が表示されなくなることを確認する。

**Acceptance Scenarios**:

1. **Given** 保護者が2台の端末を登録している状態で、**When** 子供アカウント管理画面を開く、**Then** 2台の端末名・登録日・最終利用日が表示され、今使っている端末には「この端末」と表示される
2. **Given** 上記の一覧で、**When** 片方の端末の「解除」を押し確認ダイアログで「解除する」を選ぶ、**Then** 一覧からその端末が消える
3. **Given** 端末の登録が解除された状態で、**When** その端末で子供ログイン画面を開く（または開いたまま再読み込みする）、**Then** US2-1 と同じ案内が表示され、端末に保存されたトークンは削除される
4. **Given** 保護者 A が、**When** 保護者 B の端末の ID を指定して解除 API を呼ぶ、**Then** 404 が返り、B の端末は解除されない

---

### Edge Cases

- 保護者が登録済みの端末で再度ボタンを押す → ボタンは表示されない（「登録済み」表示）。端末側のトークンがサーバー上で無効になっていた場合は、再登録できる状態に戻る
- 1家庭の登録端末数の上限（10台）に達している → 「登録できる端末は10台までです。使っていない端末を解除してください」と表示
- 子供が子供用端末でログアウトした → 子供ログイン画面（自分の家庭の子供一覧）に戻る
- 保護者が子供用端末でログアウトした → 端末の登録は維持される
- 子供アカウントが停止中 → 一覧に表示しない（既存仕様どおり）
- 子供が0人の家庭で端末を登録 → 子供ログイン画面に「まだ子供のアカウントがありません。おうちの人に作ってもらってね」と表示
- ブラウザのデータ消去で端末トークンが消えた → 未登録の端末として扱う（サーバー上の古い登録は保護者が一覧から解除できる）
- 保護者アカウントが削除された → その保護者の端末登録もすべて削除される

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 保護者は、ログイン中の端末を子供用として登録できなければならない。登録時に端末名（1〜30文字）を付ける
- **FR-002**: 登録時、システムは推測不可能な端末トークン（256ビット以上の乱数）を発行し、端末にのみ保存する。サーバーにはトークンのハッシュ値だけを保存する
- **FR-003**: 保護者ログインだけでは端末を登録してはならない
- **FR-004**: 子供一覧の取得は有効な端末トークンを必須とし、その端末を登録した保護者の有効な子供だけを返さなければならない
- **FR-005**: 子供の PIN ログインは有効な端末トークンを必須とし、ログインしようとする子供がその端末を登録した保護者の子供でなければ拒否しなければならない。この拒否は PIN の失敗回数に数えない
- **FR-006**: 認証不要で全子供を返す `GET /api/child-accounts/public` を廃止しなければならない
- **FR-007**: 保護者は自分が登録した端末の一覧（端末名・登録日時・最終利用日時）を閲覧できなければならない。他の保護者の端末は閲覧できない
- **FR-008**: 保護者は自分が登録した端末の登録を解除できなければならない。解除した端末のトークンは直ちに無効になる
- **FR-009**: 端末トークンが使われるたびに、最終利用日時を更新する（ただし更新は1分に1回程度で十分）
- **FR-010**: 1人の保護者が登録できる端末は最大10台とする
- **FR-011**: 子供ログイン画面は、端末トークンが無効と判明した時点で端末側のトークンを削除し、未登録の案内を表示しなければならない
- **FR-012**: 子供向けの案内文はやさしい日本語（小学3年生が読める漢字・表現）で表示する

### Key Entities

- **RegisteredDevice（登録端末）**: 子供用として登録された端末。属性: ID、保護者 ID、端末名、トークンのハッシュ値（一意）、登録日時、最終利用日時。保護者が削除されると連鎖削除される

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 未登録の端末から、どの API を使っても子供の名前・学年・アバターを1件も取得できない
- **SC-002**: 登録済みの端末から、他の家庭の子供の情報を1件も取得できず、他の家庭の子供としてログインもできない
- **SC-003**: 保護者は、端末登録の開始から子供がログインできる状態になるまでを1分以内に完了できる
- **SC-004**: 登録を解除した端末は、次に子供ログイン画面を開いた時点（または再読み込みした時点）で子供の一覧を表示しなくなる
- **SC-005**: 既存の子供ログイン関連テストがすべて端末トークンを使う形で成功する
