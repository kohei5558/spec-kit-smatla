# Feature Specification: 景品の家庭ごとの管理

**Feature Branch**: `007-family-rewards`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月10日
**Status**: Implemented
**Input**: User description: "景品が全家庭で共有されており、他の家庭の保護者が編集・削除できる。家庭ごとに分け、初期景品は保護者の登録時にコピーする"

## 背景

現在、景品（Reward）には家庭の情報がない。初期景品20種類が DB 初期化時に全家庭共通で1セットだけ作られ、どの保護者も全家庭の景品を閲覧・編集・削除でき、子供は全家庭の景品と交換申請できる。在庫も全家庭で共有されるため、ある家庭の交換で他の家庭の在庫が減る。景品は各家庭の保護者が実物を用意して渡すものであり、家庭ごとに管理するのが自然である。

## Clarifications

### Session 2026-10-10

- Q: 初期景品20種類をどう扱うか？ → A: 保護者の新規登録時に、20種類をその家庭の景品としてコピーする。コピー後は家庭ごとに自由に編集・削除できる
- Q: 既存 DB にある家庭の情報がない景品はどうするか？ → A: どの家庭にも表示しない（本番は未公開のため移行は不要。開発用 DB は作り直す）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 保護者は自分の家庭の景品だけを管理する (Priority: P1)

保護者の景品管理画面には自分の家庭の景品だけが表示され、追加・編集・削除も自分の家庭の景品に対してだけ行える。

**Why this priority**: 他の家庭の景品を変更・削除できるのは、公開前に必ず直すべき問題。

**Independent Test**: 2つの家庭を作り、それぞれの保護者で景品一覧を取得・更新・削除し、他の家庭の景品が見えず変更できないことを確認する。

**Acceptance Scenarios**:

1. **Given** 保護者 A と B がそれぞれ景品を登録している状態で、**When** A が景品一覧を開く、**Then** A の家庭の景品だけが表示される
2. **Given** 上記の状態で、**When** A が B の景品の ID を指定して取得・更新・削除する、**Then** 404 が返り、B の景品は変更されない
3. **Given** A が景品を新規登録した状態で、**When** B が景品一覧を開く、**Then** A が登録した景品は表示されない

---

### User Story 2 - 子供は自分の家庭の景品とだけ交換できる (Priority: P1)

子供の景品画面には自分の家庭の景品だけが表示され、交換・交換申請も自分の家庭の景品に対してだけ行える。

**Why this priority**: 他の家庭の景品と交換できると、ポイントの使い道や在庫が家庭間で混ざる。US1 と同時に必要。

**Independent Test**: 2つの家庭を作り、A の子供で景品一覧・交換・交換申請を行い、B の景品が見えず交換できないことを確認する。

**Acceptance Scenarios**:

1. **Given** A・B の家庭に景品がある状態で、**When** A の子供が景品一覧を開く、**Then** A の家庭の景品だけが表示される
2. **Given** 上記の状態で、**When** A の子供が B の景品の ID で交換・交換申請する、**Then** 404 が返り、ポイントも在庫も変わらない
3. **Given** A と B に同じ初期景品（例: うまい棒）がある状態で、**When** A の子供がうまい棒と交換する、**Then** A のうまい棒の在庫だけが減り、B の在庫は変わらない

---

### User Story 3 - 新しい家庭には初期景品が用意される (Priority: P2)

保護者が新規登録すると、初期景品20種類がその家庭の景品として登録され、すぐに使い始められる。

**Why this priority**: 使い始めの手間を減らすため。US1・US2 の分離がないと意味をなさないため P2。

**Independent Test**: 保護者を新規登録し、景品一覧に初期景品20種類が自分の家庭の景品として表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 保護者が新規登録した直後に、**When** 景品一覧を開く、**Then** 初期景品20種類が表示される
2. **Given** 2つの家庭が新規登録した状態で、**When** A が初期景品の1つの必要ポイントを変更する、**Then** B の同じ景品の必要ポイントは変わらない
3. **Given** 開発環境の初回起動で、**When** デモ用保護者（parent@example.com）が景品一覧を開く、**Then** 初期景品20種類が表示される

### Edge Cases

- 初期景品のコピーに失敗した場合 → 保護者の登録自体は成功させ、景品0件で始まる（保護者は自分で追加できる）
- 家庭の情報がない既存の景品 → どの家庭にも表示されず、交換もできない
- 保護者ダッシュボードの「景品数」 → 自分の家庭の景品だけを数える
- 交換済み・申請中の景品を削除しようとする → 現在の動作（参照があれば削除できない）を変えない

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 景品はどの家庭（保護者）のものかを持たなければならない
- **FR-002**: 景品の一覧・詳細は、保護者は自分の家庭、子供は自分の保護者の家庭の景品だけを返さなければならない
- **FR-003**: 景品の更新・削除は、自分の家庭の景品に対してだけ行えなければならない。他の家庭の景品は存在しない扱い（404）とする
- **FR-004**: 景品の新規登録時は、登録した保護者の家庭の景品としなければならない
- **FR-005**: 子供の景品交換・交換申請は、自分の家庭の景品に対してだけ行えなければならない
- **FR-006**: 保護者の新規登録時（開発環境のデモ保護者の作成時を含む）に、初期景品20種類をその家庭の景品としてコピーしなければならない
- **FR-007**: DB 初期化時に全家庭共通の景品を作成してはならない
- **FR-008**: 保護者ダッシュボードの景品の集計は、自分の家庭の景品だけを対象としなければならない

### Key Entities

- **Reward（景品）**: 既存の属性に「家庭の保護者 ID（ParentId）」を追加する。保護者 ID でインデックスを張る。在庫は家庭ごとの景品に対して管理される

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: どの保護者・子供の操作でも、他の家庭の景品を1件も閲覧・変更・交換できない
- **SC-002**: ある家庭の交換で、他の家庭の景品の在庫が変化しない
- **SC-003**: 新規登録した保護者は、登録直後に景品の追加なしで子供に交換させられる
