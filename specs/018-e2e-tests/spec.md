# Feature Specification: 画面の流れの自動テスト（E2E）

**Feature Branch**: `feature/018-e2e-tests`
**Created**: 2026年10月27日
**Status**: Implemented
**Input**: Issue #30「主要な画面の流れの自動テスト（E2E）を導入する」

## 背景

これまでの画面の不具合（メニューのリンク先の誤り、画面と API の名前の食い違い、初期景品の画像が出ない、同じ PIN の警告が本物のサーバーでだけエラーになる、既存の景品の画像を変えるとエラー など）は、API の結合テストでは見つからず、毎回 Playwright の使い捨てのスクリプトで確認していた。これをリポジトリに残る自動テストにする。

## Clarifications

### Session 2026-10-27

- Q: 何で書く？ → A: Node の Playwright Test（`e2e/`）。失敗したときのスクショと操作の記録（トレース）が残る
- Q: CI でいつ動かす？ → A: PR ごと。今のビルド・テストとは別のジョブで同時に動かす
- Q: 範囲は？ → A: Issue の保護者・子供の主な流れ ＋ 各単元（あまりのあるわり算・時こく・単位・文章問題）を1問ずつ

## 仕組み

- テストのたびに、本物の API（Development、まっさらな SQLite の DB `e2e/.data/e2e.db`）と画面を起動する。デモの家族（保護者 `parent@example.com`、花子・次郎）はシードで作られる
- 問題の正解は、API が返さないため E2E 用の DB から読む（`node:sqlite`）
- 画面の例外と API の 500 番台は、どのテストでも失敗にする
- 順番: setup（保護者ログイン・端末登録）→ parent（保護者）と child（子供）→ approve（子供の交換申請を保護者が承認）。DB を共有し、ログインの回数制限（15分で5回）もあるので1つずつ動かし、保護者のログインは setup の1回だけにする

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 主な流れが壊れていないことを PR ごとに確かめる (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 保護者、**When** ダッシュボードとメニューの各リンクを開く、**Then** 404 にならず、子供のアバターの画像が出る
2. **Given** 保護者、**When** 景品を画像つきで追加し、画像を変えて編集する、**Then** どちらも保存され、画像が出る
3. **Given** 保護者、**When** ほかの子と同じ PIN で子供アカウントを作る、**Then** 注意が出て、保存される
4. **Given** 端末登録ずみ、**When** 子供でログインしてメニューの各リンクを開く、**Then** 404・読み込みの失敗にならない
5. **Given** 子供、**When** 足し算を解く、**Then** 正解・不正解が正しく判定され、けたの多い問題はひっ算の形
6. **Given** 子供、**When** あまりのあるわり算・時こく・単位・文章問題を1問ずつ解く、**Then** 欄の数と単位が合い、正解になる
7. **Given** 子供、**When** 学習結果を開く、**Then** 種類ごとのタブと学習記録が出る
8. **Given** 子供、**When** デイリーチャレンジに正解する、**Then** 今日はおわりになる
9. **Given** 子供、**When** 初期景品の交換を申請する、**Then** 申請中になり、保護者が詳細（初期景品の画像）を見て承認できる

### Edge Cases

- 開発中の API・画面が起動していると、ポートが重なって動かない（いつもまっさらな DB で動かすため、起動中のサーバーは使わない）

## Requirements _(mandatory)_

- **FR-001**: 本物の API と画面を起動して動かさなければならない（テスト用サーバーではない）
- **FR-002**: PR ごとに CI で動き、失敗したらレポート（スクショ・トレース）を残さなければならない
- **FR-003**: ほかのテストの結果に頼らずに、毎回まっさらな DB から始めなければならない

## Success Criteria _(mandatory)_

- **SC-001**: 上のシナリオがすべて自動で確かめられる（ローカルで約2分）
- **SC-002**: これまでの不具合（メニューのリンク先の誤りなど）をわざと入れると、テストが失敗する
