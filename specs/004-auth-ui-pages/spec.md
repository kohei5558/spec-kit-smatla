# Feature Specification: Authentication UI Pages

**Feature Branch**: `004-auth-ui-pages`  
**Created**: 2026年2月7日  
**Status**: Draft  
**Input**: User description: "ログイン画面が必要です。また、パスワードを忘れた場合の変更画面と、ユーザー新規作成画面も必要です。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - Parent Login (Priority: P1)

保護者がアプリケーションにアクセスする際、メールアドレスとパスワードを使用してログインできる必要があります。

**Why this priority**: システムへの基本的なアクセス手段であり、他のすべての機能を使用するための前提条件です。

**Independent Test**: メールアドレスとパスワードの入力フィールドを持つログイン画面にアクセスし、有効な認証情報を入力してログインボタンをクリックすることで、保護者ダッシュボードにリダイレクトされることを確認できます。

**Acceptance Scenarios**:

1. **Given** ログイン画面が表示されている、**When** 有効なメールアドレスとパスワードを入力してログインボタンをクリック、**Then** 保護者ダッシュボードにリダイレクトされる
2. **Given** ログイン画面が表示されている、**When** 無効なメールアドレスまたはパスワードを入力してログインボタンをクリック、**Then** エラーメッセージが表示され、ログイン画面に留まる
3. **Given** ログイン画面が表示されている、**When** 必須フィールドが空のままログインボタンをクリック、**Then** 入力検証エラーメッセージが表示される
4. **Given** ログイン画面で「ログイン状態を保持する」をチェックせずにログイン、**When** ブラウザを閉じて再度アクセス、**Then** ログイン画面にリダイレクトされる
5. **Given** ログイン画面で「ログイン状態を保持する」をチェックしてログイン、**When** ブラウザを閉じて再度アクセス、**Then** 自動的にログイン状態で保護者ダッシュボードが表示される

---

### User Story 2 - Password Reset (Priority: P2)

保護者がパスワードを忘れた場合、登録済みのメールアドレスを使用してパスワードをリセットできる必要があります。

**Why this priority**: ユーザーがアカウントにアクセスできなくなる事態を防ぎ、カスタマーサポートへの問い合わせを削減します。

**Independent Test**: ログイン画面から「パスワードを忘れた」リンクをクリックし、メールアドレスを入力してリセットリンクを受信し、新しいパスワードを設定できることを確認できます。

**Acceptance Scenarios**:

1. **Given** ログイン画面が表示されている、**When** 「パスワードを忘れた」リンクをクリック、**Then** パスワードリセット画面に遷移する
2. **Given** パスワードリセット画面が表示されている、**When** 登録済みのメールアドレスを入力して送信ボタンをクリック、**Then** リセットリンクを含むメールが送信され、確認メッセージが表示される
3. **Given** パスワードリセットメールを受信している、**When** メール内のリセットリンクをクリック、**Then** 新しいパスワード設定画面に遷移する
4. **Given** 新しいパスワード設定画面が表示されている、**When** 有効な新しいパスワードを2回入力して送信、**Then** パスワードが更新され、ログイン画面にリダイレクトされる
5. **Given** パスワードリセット画面が表示されている、**When** 登録されていないメールアドレスを入力して送信、**Then** セキュリティ上の理由から、同じ確認メッセージが表示される（アカウントの存在を明かさない）

---

### User Story 3 - Parent Account Creation (Priority: P3)

新しい保護者がアカウントを作成し、システムを使い始めることができる必要があります。

**Why this priority**: 新規ユーザーの獲得とオンボーディングを可能にします。既存ユーザーのログインとパスワードリセットの後に実装することで、基本的な認証フローを優先します。

**Independent Test**: 新規登録画面にアクセスし、必要な情報（メールアドレス、パスワード、表示名など）を入力して登録ボタンをクリックすることで、アカウントが作成され、初回ログイン状態になることを確認できます。

**Acceptance Scenarios**:

1. **Given** ログイン画面が表示されている、**When** 「新規登録」リンクをクリック、**Then** 新規登録画面に遷移する
2. **Given** 新規登録画面が表示されている、**When** 必要な情報（メールアドレス、パスワード、表示名）を入力して登録ボタンをクリック、**Then** アカウントが作成され、保護者ダッシュボードにリダイレクトされる
3. **Given** 新規登録画面が表示されている、**When** 既に登録済みのメールアドレスを入力して登録ボタンをクリック、**Then** エラーメッセージが表示される
4. **Given** 新規登録画面が表示されている、**When** パスワード強度要件を満たさないパスワードを入力、**Then** パスワード強度エラーメッセージが表示される
5. **Given** 新規登録画面が表示されている、**When** 必須フィールドが空のまま登録ボタンをクリック、**Then** 入力検証エラーメッセージが表示される
6. **Given** 新規登録画面が表示されている、**When** パスワード確認フィールドが元のパスワードと一致しない、**Then** エラーメッセージが表示される

---

### Edge Cases

- ユーザーが既にログイン済みの状態でログイン画面にアクセスした場合、どうなるか？（適切なダッシュボードにリダイレクト）
- パスワードリセットリンクの有効期限が切れた場合、エラーメッセージとリセット画面への直接リンクを表示
- レート制限により一時的にブロックされたユーザーが再試行可能になるタイミングは？（15分後）
- メール送信が失敗した場合でも、セキュリティ上の理由から常に同じ成功メッセージを表示する
- 不正なパスワードリセットトークンでアクセスした場合、どう処理するか？
- ネットワークエラーでログイン/登録が失敗した場合、適切なエラーメッセージが表示されるか？
- 子供ユーザー（PIN認証）のログイン画面は別途必要か、同じ画面で切り替え可能にするか？

## Requirements _(mandatory)_

### Functional Requirements

#### Login Page

- **FR-001**: システムはログイン画面を提供しなければならない
- **FR-002**: ログイン画面はメールアドレス入力フィールドを含まなければならない
- **FR-003**: ログイン画面はパスワード入力フィールド（マスク表示）を含まなければならない
- **FR-004**: ログイン画面はログインボタンを含まなければならない
- **FR-005**: ログイン画面は「パスワードを忘れた」リンクを含まなければならない
- **FR-006**: ログイン画面は「新規登録」リンクを含まなければならない
- **FR-006a**: ログイン画面は「ログイン状態を保持する」チェックボックスを含まなければならない（デフォルトはオフ）
- **FR-006b**: チェックボックスがオフの場合、JWTトークンはブラウザセッション終了時に失効しなければならない
- **FR-006c**: チェックボックスがオンの場合、JWTトークンは長期間（例：30日間）有効でなければならない
- **FR-007**: システムは入力されたメールアドレスの形式を検証しなければならない
- **FR-008**: システムはログイン失敗時に適切なエラーメッセージを表示しなければならない
- **FR-008a**: システムは同一IPアドレスからの短時間（例：15分以内）に複数回（例：5回以上）のログイン失敗を検知しなければならない
- **FR-008b**: レート制限に達した場合、システムは一時的に（例：15分間）そのIPアドレスからのログイン試行をブロックしなければならない
- **FR-008c**: レート制限中のログイン試行には「しばらくしてから再度お試しください」というメッセージを表示しなければならない
- **FR-009**: システムはログイン成功時にユーザーの役割に応じた適切なダッシュボードにリダイレクトしなければならない
- **FR-010**: パスワードフィールドは「表示/非表示」切り替え機能を提供することが望ましい

#### Password Reset Page

- **FR-011**: システムはパスワードリセット画面を提供しなければならない
- **FR-012**: パスワードリセット画面はメールアドレス入力フィールドを含まなければならない
- **FR-013**: システムは有効なメールアドレスが入力された際にパスワードリセットリンクを含むメールを送信しなければならない
- **FR-013a**: メール送信に失敗した場合でも、セキュリティ上の理由から、常に同じ成功メッセージを表示しなければならない
- **FR-013b**: システムはメール送信の失敗を内部的にログに記録しなければならない（管理者による監視用）
- **FR-014**: パスワードリセットリンクは一定期間（24時間を推奨）のみ有効でなければならない
- **FR-014a**: 有効期限切れのパスワードリセットリンクにアクセスした場合、「リンクの有効期限が切れています」というメッセージを表示しなければならない
- **FR-014b**: 有効期限切れメッセージには、パスワードリセット画面へ戻るリンクを含まなければならない
- **FR-015**: システムは新しいパスワード設定画面を提供しなければならない
- **FR-016**: 新しいパスワード設定画面はパスワード入力フィールドとパスワード確認フィールドを含まなければならない
- **FR-017**: システムは2つのパスワードフィールドが一致することを検証しなければならない
- **FR-018**: システムはパスワード強度要件を検証しなければならない（最小8文字、大文字・小文字・数字・記号を含む）
- **FR-019**: システムはパスワードリセット完了後、ログイン画面にリダイレクトしなければならない
- **FR-020**: セキュリティ上、存在しないメールアドレスでも同じ成功メッセージを表示しなければならない

#### Account Creation Page

- **FR-021**: システムは新規アカウント作成画面を提供しなければならない
- **FR-022**: アカウント作成画面はメールアドレス入力フィールドを含まなければならない
- **FR-023**: アカウント作成画面は表示名入力フィールドを含まなければならない
- **FR-023a**: アカウント作成時には表示名、メールアドレス、パスワードのみを収集し、追加のプロフィール情報（電話番号、住所等）は収集しない
- **FR-024**: アカウント作成画面はパスワード入力フィールドを含まなければならない
- **FR-025**: アカウント作成画面はパスワード確認入力フィールドを含まなければならない
- **FR-026**: システムはメールアドレスの重複をチェックしなければならない
- **FR-027**: システムはアカウント作成時にパスワード強度要件を検証しなければならない
- **FR-028**: システムはアカウント作成成功後、自動的にログイン状態にし、保護者ダッシュボードにリダイレクトしなければならない
- **FR-029**: アカウント作成画面は「既にアカウントをお持ちの方」としてログイン画面へのリンクを含まなければならない

#### General UI Requirements

- **FR-030**: すべての画面はレスポンシブデザインでなければならない（モバイル、タブレット、デスクトップに対応）
- **FR-031**: すべてのエラーメッセージはユーザーフレンドリーで具体的でなければならない
- **FR-032**: すべてのフォームは送信中のローディング状態を表示しなければならない
- **FR-033**: すべての必須フィールドは視覚的に明示されなければならない
- **FR-034**: すべての画面はアクセシビリティ基準（WCAG 2.1レベルAA）を満たすことが望ましい

### Key Entities

- **User Account**: ユーザーのアカウント情報（メールアドレス、パスワードハッシュ、表示名、役割、作成日時、最終ログイン日時）
- **Password Reset Token**: パスワードリセット用の一時トークン（トークン値、ユーザー識別子、有効期限、使用済みフラグ）
- **Session**: ログイン状態を管理するセッション情報（セッションID、ユーザー識別子、有効期限）

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 保護者ユーザーがログイン画面で認証情報を入力してから保護者ダッシュボードが表示されるまで5秒以内に完了する
- **SC-002**: 新規ユーザーがアカウント作成画面で必要情報を入力してから登録完了まで3分以内に完了する
- **SC-003**: パスワードリセット機能を使用してパスワードを変更する全プロセスを10分以内に完了できる
- **SC-004**: ログイン失敗時に具体的で理解しやすいエラーメッセージが表示され、90%以上のユーザーが次のアクションを理解できる
- **SC-005**: すべての認証画面がモバイルデバイスで正しく表示され、タッチ操作で使用できる
- **SC-006**: パスワードリセットメールが送信要求後1分以内にユーザーのメールボックスに配信される
- **SC-007**: 新規アカウント作成後、95%以上のユーザーが最初の試行で正常にログインできる
- **SC-008**: すべての認証画面が主要ブラウザ（Chrome、Firefox、Safari、Edge）で一貫した動作をする

## Assumptions

1. **認証メカニズム**: バックエンドは既にJWT認証とASP.NET Core Identityを実装済みであると仮定
2. **メール送信**: メール送信サービスは既に設定済みで、SMTPまたはサードパーティサービス経由で送信可能であると仮定
3. **セッション管理**: JWT トークンをローカルストレージまたはセキュアなCookieに保存して管理する
4. **パスワード要件**: 最小8文字、大文字・小文字・数字・記号を各1文字以上含む（業界標準）
5. **リセットトークン有効期限**: 24時間（セキュリティと使いやすさのバランス）
6. **ユーザー役割**: この機能では保護者（Parent）ユーザーのアカウント作成とログインに焦点を当てる。子供ユーザーのPIN認証は既存機能として存在すると仮定
7. **UI フレームワーク**: Blazor WebAssemblyを使用（既存プロジェクト構造から判断）
8. **多言語対応**: 日本語のみでよいと仮定（必要に応じて後から多言語対応可能な設計にする）
9. **アカウントロック**: 初期バージョンでは実装せず、将来的な拡張として検討
10. **メール認証**: アカウント作成直後のメール認証は必須ではないが、将来的な拡張として検討可能

## Out of Scope

以下の機能は本機能の範囲外とします：

1. **子供ユーザーのPINログイン画面**: 既存機能として実装済みと仮定
2. **多要素認証（MFA）**: 将来的な拡張機能として別途検討
3. **ソーシャルログイン**: Google、Facebook等のOAuth2連携は別機能として検討
4. **アカウント削除機能**: 別途プライバシー機能として実装
5. **プロフィール編集画面**: ログイン後の機能として別途実装
6. **メールアドレス変更機能**: セキュリティ要件が高いため別機能として検討
7. **管理者用ログイン画面**: 管理者機能として別途検討
8. **ログイン履歴の表示**: セキュリティ機能として別途検討
9. **アカウントロック機能**: セキュリティ機能として将来的に検討
10. **CAPTCHAまたはbot対策**: 初期バージョンでは不要、必要に応じて追加

## Dependencies

1. **バックエンド認証API**: `/api/auth/login`、`/api/auth/register`、`/api/auth/forgot-password`、`/api/auth/reset-password` などのエンドポイントが利用可能である必要がある
2. **メール送信サービス**: パスワードリセットメールを送信するための設定済みメール送信機能
3. **ASP.NET Core Identity**: ユーザー管理とパスワードハッシュ化
4. **JWT トークン生成**: 認証成功時のトークン発行機能
5. **既存のBlazorコンポーネント**: Layout、AuthGuardなどの既存コンポーネントとの統合

## Clarifications

### Session 2026-02-07

- Q: セッション保持の動作はどうすべきか？ → A: 「記憶する」チェックボックスで選択可能（デフォルトはセッション終了で失効）
- Q: パスワードリセットメール送信失敗時の動作は？ → A: 常に成功メッセージを表示（実際の送信状況に関わらず）
- Q: 新規アカウント作成時に収集する情報は？ → A: 表示名とメールアドレスのみ（最小限の情報）
- Q: ログイン失敗回数の制限とアカウントロック対策は？ → A: レート制限のみ実装（同一IPから短時間に複数回失敗した場合、一時的にブロック）
- Q: パスワードリセットリンクの有効期限切れ時の動作は？ → A: 「リンクの有効期限が切れています」というメッセージと、パスワードリセット画面への直接リンクを表示

## Notes

- この仕様書は認証UIのフロントエンド画面に焦点を当てており、バックエンドAPIは既に実装済みであることを前提としています
- セキュリティベストプラクティスに従い、パスワードは常にマスク表示、HTTPSでの通信、適切なエラーメッセージ（詳細すぎる情報を避ける）を実装する必要があります
- アクセシビリティとモバイル対応は、幅広いユーザー層にリーチするために重要です
