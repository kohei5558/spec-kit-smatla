# Feature Specification: あまりのあるわり算

**Feature Branch**: `009-division-with-remainder`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月10日
**Status**: Draft
**Input**: User description: "小3の重要単元『あまりのあるわり算』を練習できるようにする"

## 背景

答えは整数1つという前提で作られており、問題・学習記録・回答 API・問題画面のどれも「商とあまり」の2つの答えを扱えない。008 で割り算の難易度を整理したが、あまりのある割り算は対象外としていた。

## Clarifications

### Session 2026-10-10

- Q: 既存の「割り算」に混ぜるか、新しい種類にするか？ → A: 新しい計算の種類「あまりのあるわり算」にする（ホーム画面で選べる5種類目。「すべて」にも混ざる）
- Q: 答えの入力方法は？ → A: 「17 ÷ 5 = [ 3 ] あまり [ 2 ]」のように商とあまりの入力欄を2つ出す

## 難易度表（あまりのあるわり算）

すべての問題であまりは1以上（割り切れる問題は出さない）、あまりは割る数より小さい。

| 難易度 | 内容 | 例 |
|---|---|---|
| 1 | ÷2・÷3（商1〜9） | 7 ÷ 2 = 3 あまり 1 |
| 2 | ÷4・÷5（商1〜9） | 23 ÷ 4 = 5 あまり 3 |
| 3 | ÷6・÷7（商1〜9） | 45 ÷ 7 = 6 あまり 3 |
| 4 | ÷8・÷9（商1〜9） | 70 ÷ 9 = 7 あまり 7 |
| 5 | ÷2〜÷9（商1〜9、九九の範囲すべて） | 58 ÷ 6 = 9 あまり 4 |
| 6 | 2桁÷1桁（商2桁、各位がそのまま割れてあまりが出る） | 37 ÷ 3 = 12 あまり 1 |
| 7 | 2桁÷1桁（商2桁） | 75 ÷ 4 = 18 あまり 3 |
| 8 | 3桁÷1桁（商2桁） | 158 ÷ 6 = 26 あまり 2 |
| 9 | 3桁÷1桁（商3桁、割る数2〜5） | 487 ÷ 3 = 162 あまり 1 |
| 10 | 3桁÷1桁（商3桁、割る数6〜9） | 925 ÷ 7 = 132 あまり 1 |

小3の内容は難易度1〜5（九九の範囲）。6〜10は小4の先取り。各難易度30問（組み合わせが30通り未満の難易度1はありうる問題すべて）。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - あまりのあるわり算を選んで練習する (Priority: P1)

子供はホーム画面で「あまりのあるわり算」を選び、商とあまりを2つの欄に入力して答える。両方合っていれば正解になる。

**Why this priority**: 本機能の目的そのもの。

**Independent Test**: 子供でログインし、「あまりのあるわり算」を選んで問題を解き、商とあまりの両方が合っているときだけ正解になることを確認する。

**Acceptance Scenarios**:

1. **Given** 子供がホーム画面を開いている、**When** 計算の種類を見る、**Then** 「あまりのあるわり算」が5種類目として選べる
2. **Given** 「あまりのあるわり算」を選んだ、**When** 問題画面を開く、**Then** 「17 ÷ 5 =」のあとに商の欄と「あまり」の欄が表示される
3. **Given** 17 ÷ 5 の問題で、**When** 商 3・あまり 2 と答える、**Then** 正解になりポイントがもらえる
4. **Given** 17 ÷ 5 の問題で、**When** 商 3・あまり 1、または 商 2・あまり 7 と答える、**Then** 不正解になり「こたえは 3 あまり 2」と表示される
5. **Given** 計算の種類で「すべて」を選んだ、**When** 問題を解き続ける、**Then** あまりのあるわり算も出ることがある
6. **Given** 割り切れる「割り算」や他の種類の問題では、**When** 問題画面を開く、**Then** 入力欄は今までどおり1つ

---

### User Story 2 - 学習結果で別に集計される (Priority: P2)

学習結果画面と保護者の統計で、「あまりのあるわり算」が他の種類と別に集計される。

**Why this priority**: 苦手な単元を見つけるため。US1 がないと意味がないため P2。

**Independent Test**: あまりのあるわり算を数問解き、学習結果の種類別の表に「あまりのあるわり算」の行が出ることを確認する。

**Acceptance Scenarios**:

1. **Given** あまりのあるわり算を解いた、**When** 学習結果画面を開く、**Then** 種類別の集計に「あまりのあるわり算」が表示される
2. **Given** 学習記録の一覧で、**When** あまりのあるわり算の記録を見る、**Then** 子供の答えが「3 あまり 2」の形で表示される

### Edge Cases

- あまりの欄を空欄のまま答える → 答えるボタンを押せない（商も同じ）
- 割り切れる問題に「あまり」を送ってきた場合（古い画面や API の直接呼び出し） → あまりは無視し、商だけで判定する（既存どおり）
- デイリーチャレンジ（答えは1つ）には、あまりのあるわり算を選ばない
- 既存の DB の問題は入れ替わらない（問題は DB が空のときだけ作られる）。開発用 DB は作り直す

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 計算の種類に「あまりのあるわり算」を追加しなければならない
- **FR-002**: 問題は正解の商に加えて正解のあまりを持ち、あまりのあるわり算の問題だけがあまりを持つ
- **FR-003**: 問題の取得 API は、その問題があまりを答える問題かどうかを返さなければならない（正解は返さない）
- **FR-004**: 回答 API は商とあまりを受け取り、あまりを持つ問題では両方が正しいときだけ正解としなければならない
- **FR-005**: 回答結果は正解のあまりも返し、画面は不正解時に「こたえは 商 あまり あまり」の形で表示しなければならない
- **FR-006**: 学習記録は子供が答えたあまりも保存しなければならない
- **FR-007**: 問題は難易度表に従って作らなければならない（あまりは1以上・割る数未満）
- **FR-008**: デイリーチャレンジの問題には、あまりのあるわり算を選んではならない
- **FR-009**: 計算の種類を表示するすべての画面（ホームの種類選択、問題画面、学習結果、学習記録一覧）で「あまりのあるわり算」を日本語で表示しなければならない

### Key Entities

- **Problem**: `CorrectRemainder`（int?、あまりのあるわり算のみ）を追加
- **LearningRecord**: `StudentRemainder`（int?）を追加
- **CalculationType**: `DivisionWithRemainder = 4` を追加

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 子供は「あまりのあるわり算」を選び、商とあまりを入力して答えられる
- **SC-002**: 商・あまりのどちらかが違えば必ず不正解になる
- **SC-003**: あまりのあるわり算の全問題が難易度表の条件を満たすことを自動テストで確認できる
