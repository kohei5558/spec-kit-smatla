# Feature Specification: 家族で使うための公開（無料サービス）

**Feature Branch**: `012-family-deployment`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月11日
**Status**: Implemented
**Input**: User description: "いずれ誰でも使えるように公開する。まずは自分の家族から。無料のサービスで、独自ドメインは使わない"

## 背景

今はローカルでしか動かない。公開を妨げているもの:

- 画面が API を探すアドレス（`http://localhost:5242`）と、API が受け付ける画面のアドレス（CORS）がコードに固定されている
- 保護者がアップロードした景品の画像を API サーバーのディスクに保存している（無料のサーバーは再デプロイ・再起動で消える）
- 本番で動かす手順・設定（Dockerfile、デプロイ手順）がない
- 誰でも保護者登録できる（子供のデータを預かる準備＝規約・プライバシーポリシー・退会がまだない）

## Clarifications

### Session 2026-10-11

- Q: 誰が使うか？ → A: いずれ誰でも。ただしまず自分の家族だけで使う（第1段階。一般公開は規約・プライバシーポリシー・退会・バックアップを整えてから第2段階で行う）
- Q: 公開先は？ → A: 無料のサービス。画面は Cloudflare Pages、API は Render（無料の Web Service、Docker）、DB は Neon（無料の PostgreSQL）
- Q: 独自ドメインは？ → A: 使わない（各サービスのアドレス `*.pages.dev`・`*.onrender.com` を使う）
- Q: 他人の登録は？ → A: 招待コード制。設定に招待コードがあるときは、それを入れないと保護者登録できない

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 家族がインターネット経由で使える (Priority: P1)

保護者と子供が、家のタブレットやスマホのブラウザから公開アドレスを開いて、ローカルと同じように使える。

**Independent Test**: 公開アドレスで、保護者登録 → 端末登録 → 子供ログイン → 問題を解く → 景品の交換申請 → 保護者が承認、まで通す。

**Acceptance Scenarios**:

1. **Given** 公開された画面のアドレス、**When** 保護者が招待コードを入れて登録する、**Then** 登録でき、ローカルと同じ機能が使える
2. **Given** API が止まっている（無料プランは15分アクセスがないと止まる）、**When** 画面を開く、**Then** 起きるまで待ってから使える（エラーで終わらない）
3. **Given** 保護者が景品に写真を付けた、**When** API サーバーが再起動・再デプロイされる、**Then** 写真は消えずに表示される

---

### User Story 2 - 他人は登録できない (Priority: P1)

招待コードを知らない人は保護者登録できない。

**Acceptance Scenarios**:

1. **Given** 本番の設定に招待コードがある、**When** 招待コードなし・違うコードで登録する、**Then** 登録できない
2. **Given** 招待コードの設定がない（開発環境・第2段階）、**When** 登録する、**Then** 今までどおり誰でも登録できる

---

### User Story 3 - 運営者が手順どおりに公開・更新できる (Priority: P1)

運営者（保護者本人）が、手順書どおりに各サービスのアカウントを作って公開できる。公開後は GitHub に push すると更新される。

**Acceptance Scenarios**:

1. **Given** 手順書（`docs/DEPLOY.md`）、**When** 順番に進める、**Then** Neon・Render・Cloudflare Pages の設定ができ、公開アドレスで使える
2. **Given** 公開後、**When** main に push する、**Then** 画面と API が新しい版に更新され、DB の構造の変更・問題の入れ替えも起動時に反映される

### Edge Cases

- 秘密情報（JWT の鍵、DB の接続文字列、招待コード）はリポジトリに書かず、各サービスの環境変数に入れる
- 招待コードの比較は時間で推測されない方法で行う。登録 API の回数制限（既存）も効く
- 画像は DB に保存するため、大きさに上限を設ける（既存の上限 5MB を 1MB にする）。DB の無料枠（1GB）を使い切らないため
- 画像は `<img>` で表示するためログインなしで取得できるが、アドレスは推測できない（ランダムな ID）
- 既存のアップロード画像（ディスク上）は、開発環境ではそのまま表示できる（移行はしない。本番はまだデータがない）
- メール送信（パスワード再設定）は第1段階では使わない（送信の設定がなければ、今までどおり送らない）
- 無料の DB にはバックアップの保証がない。第2段階の前にバックアップの方法を決める

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 画面が使う API のアドレスは設定（`wwwroot/appsettings*.json`）で決め、本番はデプロイ時に指定できなければならない
- **FR-002**: API が受け付ける画面のアドレス（CORS）は設定 `Cors:AllowedOrigins` で決めなければならない（開発の既定値は今のローカルのアドレス）
- **FR-003**: 設定 `Registration:InviteCode` があるとき、保護者登録は同じ招待コードを入れたときだけ成功しなければならない。登録画面に招待コードの入力欄を出す
- **FR-004**: 保護者がアップロードする景品の画像は DB に保存し、API から配信しなければならない
- **FR-005**: API は Docker で動き、Render のプロキシの後ろで正しく動かなければならない（転送ヘッダー、ヘルスチェック用の `/healthz`）
- **FR-006**: GitHub Actions で、main への push 時に画面を Cloudflare Pages へデプロイしなければならない（Cloudflare の API トークンは GitHub の Secrets に入れる）
- **FR-007**: 画面は API が起きるまでの間「じゅんびちゅう…」を表示し、タイムアウトでエラーにしない
- **FR-008**: 手順書 `docs/DEPLOY.md` に、各サービスのアカウント作成から公開・更新までを日本語で書かなければならない

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 家族が公開アドレスから、ローカルと同じ機能を使える
- **SC-002**: 招待コードなしでは保護者登録できないことを自動テストで確認できる
- **SC-003**: 再デプロイ後もアップロードした画像が表示される
