# Feature Specification: 問題の難易度を小3まで広げ、学年に応じたレベルから始める

**Feature Branch**: `008-grade3-difficulty`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月10日
**Status**: Draft
**Input**: User description: "子供が小学3年生になった。問題の難易度を小3の内容まで広げ、学年に応じたレベルから始められるようにする"

## 背景

- 問題は起動時に700問を作り置きしている。難易度1〜10の最上位でも「2桁の足し算・引き算」「九九（最大12×12）」「割り切れる割り算」までで、小3で習う3〜4桁の筆算や2〜3桁×1桁に届かない
- 出題の難易度は子供のレベルで決まるが、全員がレベル1（1桁＋1桁）から始まる。子供アカウントの学年は出題に使われていない
- 答えは整数1つ。あまりのある割り算は対象外（次の段階で扱う）

## Clarifications

### Session 2026-10-10

- Q: 今回の範囲は？ → A: 難易度1〜10を小1〜小3（一部小4の先取り）の内容に作り直し、学年に応じて始めるレベルを変える。あまりのある割り算は含めない
- Q: レベルアップの条件は変えるか？ → A: 変えない（現在の「連続正解でレベルアップ」のまま）

## 難易度表

答えはすべて0以上の整数。「くり上がり」「くり下がり」は筆算での桁上がり・桁借り。

| 難易度 | 足し算 | 引き算 | 掛け算 | 割り算（割り切れる） |
|---|---|---|---|---|
| 1 | 1桁+1桁（くり上がりなし） | 1桁-1桁 | 2・5の段 | ÷2・÷5（九九の逆） |
| 2 | 1桁+1桁（くり上がりあり） | 2桁-1桁（答え1桁、くり下がりあり） | 3・4の段 | ÷3・÷4 |
| 3 | 2桁+1桁 | 2桁-1桁 | 6・7の段 | ÷6・÷7 |
| 4 | 2桁+2桁（くり上がりなし） | 2桁-2桁（くり下がりなし） | 8・9・1の段 | ÷8・÷9・÷1 |
| 5 | 2桁+2桁（くり上がりあり） | 2桁-2桁（くり下がりあり） | 九九すべて | ÷1〜÷9（九九の逆すべて） |
| 6 | 3桁+2桁 | 3桁-2桁 | 何十×1桁（例: 30×4） | 何十÷1桁（例: 80÷4） |
| 7 | 3桁+3桁（くり上がり1回まで） | 3桁-3桁（くり下がり1回まで） | 2桁×1桁（くり上がりなし） | 2桁÷1桁（商が2桁、くり下がりなし。例: 69÷3） |
| 8 | 3桁+3桁（くり上がり2回以上） | 3桁-3桁（くり下がり2回以上） | 2桁×1桁（くり上がりあり） | 2桁÷1桁（商が2桁。例: 72÷3） |
| 9 | 4桁+3桁 | 4桁-3桁 | 3桁×1桁 | 3桁÷1桁（商が2桁。例: 144÷6） |
| 10 | 4桁+4桁 | 4桁-4桁 | 2桁×2桁 | 3桁÷1桁（商が3桁。例: 852÷4） |

小3の内容は難易度6〜8が中心（9・10は先取り）。

## 学年と始めるレベル

| 学年 | 始めるレベル | そのレベルで出る難易度 |
|---|---|---|
| 1年 | レベル1 | 1〜2 |
| 2年 | レベル3 | 3〜4 |
| 3年 | レベル5 | 5〜6（小2の復習から小3の入口） |
| 4年以上 | レベル7 | 7〜8 |

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 小3の内容の問題が出る (Priority: P1)

難易度が上がると、3桁・4桁の足し算・引き算、2〜3桁×1桁や2桁×2桁の掛け算、2〜3桁÷1桁の割り算が出題される。

**Why this priority**: 小3の子供が学年に合った計算を練習できることが本機能の目的。

**Independent Test**: 問題を作る仕組みを単体で動かし、各難易度・各計算の問題が難易度表の条件（桁数、くり上がりの有無、割り切れること）を満たすことを確認する。

**Acceptance Scenarios**:

1. **Given** 難易度8の足し算を出す、**When** 問題を見る、**Then** 3桁+3桁で、筆算でくり上がりが2回以上ある
2. **Given** 難易度9の掛け算を出す、**When** 問題を見る、**Then** 3桁×1桁である
3. **Given** 難易度7〜10の割り算を出す、**When** 問題を見る、**Then** 割り切れて、答え（商）が難易度表の桁数になる
4. **Given** どの難易度・計算でも、**When** 問題を作る、**Then** 答えは0以上の整数で、同じ難易度・計算の中に同じ問題が重複しない

---

### User Story 2 - 学年に応じたレベルから始まる (Priority: P1)

保護者が子供アカウントを作るとき、設定した学年に応じたレベルから始まる。小3なら、最初から2桁の筆算や九九すべての問題が出る。

**Why this priority**: 小3の子供が1桁の足し算から延々と始める状態を解消するため。

**Independent Test**: 学年を変えて子供アカウントを作り、最初のレベルと出題される難易度を確認する。

**Acceptance Scenarios**:

1. **Given** 保護者が学年「3年」で子供アカウントを作る、**When** 子供が最初の問題を取得する、**Then** 子供はレベル5で、難易度5〜6の問題が出る
2. **Given** 学年「1年」で作る、**When** 最初の問題を取得する、**Then** レベル1で、難易度1〜2の問題が出る
3. **Given** 学年「2年」でレベル3の子供を、**When** 保護者が学年を「3年」に変更する、**Then** レベル5に上がる
4. **Given** レベル8まで上がった学年「3年」の子供を、**When** 保護者が学年を「2年」に変更する、**Then** レベルは8のまま（自動では下げない）

### Edge Cases

- 既存の DB の問題は入れ替わらない（問題は DB が空のときだけ作られる）。開発用 DB は作り直す。本番は未公開のため移行不要
- 学年が範囲外（0以下・7以上）→ 既存の入力チェックどおり作成できない
- 問題は毎回同じ内容で作られる（乱数の種を固定）。どの環境でも同じ問題セットになり、不具合を再現しやすくする

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 問題の生成は難易度表に従わなければならない
- **FR-002**: 各計算・各難易度について30問ずつ、重複なく作らなければならない（合計1,200問）
- **FR-003**: 割り算は割り切れる問題だけを作らなければならない
- **FR-004**: 子供アカウントの作成時、学年に応じた始めるレベルを学習者に設定しなければならない
- **FR-005**: 学年の変更で始めるレベルが現在のレベルより高くなる場合はレベルを上げ、低くなる場合は変えてはならない
- **FR-006**: 問題を作る仕組みは DB に依存せず単体でテストできなければならない

### Key Entities

- 変更なし（問題・レベル・学習者の既存の構造を使う）

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 学年「3年」で作った子供の最初の問題が、難易度5〜6（2桁の筆算・九九すべて・3桁+2桁など）になる
- **SC-002**: 難易度6〜8に、小3で習う計算（3桁の筆算、何十×1桁、2桁×1桁、2桁÷1桁）がすべて含まれる
- **SC-003**: 1,200問すべてが難易度表の条件を満たすことを自動テストで確認できる
