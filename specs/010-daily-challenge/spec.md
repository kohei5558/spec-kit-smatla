# Feature Specification: デイリーチャレンジの作り直し

**Feature Branch**: `010-daily-challenge`（作業は `claude/project-status-m9txmv` 上で実施）
**Created**: 2026年10月10日
**Status**: Implemented
**Input**: User description: "デイリーチャレンジの難易度が小3には難しすぎる（難易度7以上）"

## 背景

調べたところ、難易度以前に次の問題があった。

1. **画面から動いていない**: ホームの「挑戦する！」は普通の問題画面（`/problem?challengeId=…`）に移動するだけで、問題画面は `challengeId` を見ていない。チャレンジの回答 API は画面から一度も呼ばれない
2. **何度でもボーナスがもらえる**: 回答 API は同じチャレンジに何度でも答えられ、正解するたびにボーナス（難易度×5 = 35〜50 ポイント）が入る
3. **全員で1日1問**: チャレンジは全家庭・全員で共通の1問（難易度7以上）。1年生にも3年生にも同じ問題が出る
4. **時刻が UTC**: 日付の切り替わりが UTC の0時（日本時間の朝9時）
5. **レベルの扱いが通常の問題と違う**: チャレンジの回答だけ、不正解でも連続正解数がリセットされず、レベルアップの判定も別の書き方になっている

## Clarifications

### Session 2026-10-10

- Q: どの問題を出すか？ → A: 子供ごとに、その子の今のレベルに合わせて出す（1年生と3年生で別の問題）
- Q: 1日に答えられる回数は？ → A: 1日1回だけ（正解でも不正解でも、答えたらその日は終わり）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 自分に合ったチャレンジに1日1回挑戦する (Priority: P1)

子供はホーム画面の「今日のチャレンジ」から、自分のレベルに合った1問に挑戦する。正解するとボーナスポイントがもらえる。答えたらその日はもう挑戦できない。

**Why this priority**: 機能が動いていないため、これがないと何も始まらない。

**Independent Test**: 子供でログインし、ホームの「挑戦する！」から問題に答え、正解ならボーナスが入ること、同じ日にもう一度は答えられないことを確認する。

**Acceptance Scenarios**:

1. **Given** 3年生（レベル5）の子供が今日まだ挑戦していない、**When** ホーム画面を開く、**Then** 「今日のチャレンジ」に「挑戦する！」ボタンとボーナスポイントが表示される
2. **Given** 「挑戦する！」を押した、**When** チャレンジ画面が開く、**Then** その子の今のレベルで出る一番難しい難易度（レベル5なら難易度6）の問題が1問表示される
3. **Given** チャレンジの問題に正解した、**When** 結果が表示される、**Then** 「正解！」とボーナスポイント（+30）が表示され、ポイントが増える
4. **Given** チャレンジの問題に不正解だった、**When** 結果が表示される、**Then** 正解が表示され、ボーナスはもらえない
5. **Given** 今日すでに挑戦した（正解でも不正解でも）、**When** ホーム画面を開く、**Then** 「今日のチャレンジはおわり。また明日ちょうせんしてね」と結果（せいかい／ざんねん）が表示され、「挑戦する！」は出ない
6. **Given** 今日すでに挑戦した、**When** 回答 API をもう一度呼ぶ、**Then** 受け付けず（409）、ポイントは増えない
7. **Given** 同じ家庭の1年生（レベル1）と3年生（レベル5）、**When** それぞれチャレンジを開く、**Then** 1年生は難易度2、3年生は難易度6の問題になる

### User Story 2 - 日本の日付で切り替わる (Priority: P2)

チャレンジは日本時間の0時に次の日のものに切り替わる。

**Why this priority**: 朝9時に切り替わると、朝に挑戦した子が「昨日の分」として扱われ混乱する。

**Independent Test**: 日本時間の日付が変わったら新しいチャレンジになることを、時刻を差し替えられるテストで確認する。

**Acceptance Scenarios**:

1. **Given** 日本時間 10月10日 23:59 に挑戦した、**When** 日本時間 10月11日 0:00 以降にホーム画面を開く、**Then** 新しいチャレンジに挑戦できる
2. **Given** 日本時間 10月11日 8:00（UTC では 10月10日）、**When** チャレンジを開く、**Then** 10月11日のチャレンジとして扱われる

### Edge Cases

- その日に初めてチャレンジを開いたときに、その子の分を作る（夜中に全員分を作る処理は不要になるので削除する）
- チャレンジを開いたあと答える前にレベルが上がった → 問題はその日のうちは変わらない（最初に開いたときのレベルで決まる）
- その難易度にチャレンジ向きの問題がない（DB が空など） → 「今日のチャレンジはまだありません」と表示し、エラーにしない
- あまりのあるわり算はチャレンジに出さない（009 のとおり。答えが1つの問題だけ）
- 保護者はチャレンジに答えられない（子供のポイントが増えるため）。回答は子供本人だけ
- 他の家庭の子供のチャレンジは見られない・答えられない（404）
- 同じチャレンジに同時に2回答えが送られても、ボーナスは1回分だけ
- 答えられるのは今日のチャレンジだけ（前の日に開いて答えなかったチャレンジにあとから答えることはできない）
- 既存の（全員共通の）チャレンジのデータは使わない（マイグレーションで消す。まだ公開前のため）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: チャレンジは子供（学習者）ごと・日ごとに1つでなければならない
- **FR-002**: チャレンジの問題は、その子の今のレベルの最大難易度の問題から選ばなければならない（足し算・引き算・かけ算・割り算。あまりのあるわり算は除く）
- **FR-003**: ボーナスポイントは難易度によらず一定（30 ポイント。通常の問題は10ポイント）とする
- **FR-004**: 子供は1日1回だけ答えられる。2回目以降の回答は受け付けず、ポイントも増やしてはならない
- **FR-005**: 「1日」は日本時間（Asia/Tokyo）の0時で区切らなければならない
- **FR-006**: チャレンジの取得 API は、今日すでに答えたか・その結果・もらったボーナスを返さなければならない（未回答のときは正解を返さない）
- **FR-007**: チャレンジの回答は学習記録に残す（正答率に入る）。ただし通常の問題の連続正解数・レベルは変えない（チャレンジはボーナスのための特別な1問のため）
- **FR-008**: 回答は子供本人だけができる。取得・回答とも、学習者 ID の確認（自分・自分の子供以外は 404）を行わなければならない
- **FR-009**: ホーム画面の「挑戦する！」からチャレンジ専用の画面で答えられなければならない。答えたあとはホーム画面に結果を表示する

### Key Entities

- **DailyChallenge**: `StudentId` を追加し、（`StudentId`, `TargetDate`）で一意にする。回答の結果として `AnsweredAt`（日時、未回答は null）、`IsCorrect`（bool?）、`StudentAnswer`（int?）を持つ

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 子供はホーム画面からチャレンジに挑戦でき、正解するとボーナスが1回だけ入る
- **SC-002**: 3年生（レベル5）には難易度6、1年生（レベル1）には難易度2の問題が出る
- **SC-003**: 同じ日に2回答えてもボーナスは増えないことを自動テストで確認できる
