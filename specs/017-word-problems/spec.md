# Feature Specification: 文章問題

**Feature Branch**: `feature/017-word-problems`
**Created**: 2026年10月26日
**Status**: Implemented
**Input**: User description: "文章問題で、どの計算を使うか判断する力をつける"

## 背景

計算の練習はできるが、「文章を読んで、どの計算を使うか決める」練習ができない。文章問題を、保護者が確認したひな形（[templates.md](./templates.md)）に数字を入れて作る（AI などで毎回文章を作ることはしない。子供に見せる文を事前に確認できるようにするため）。

## Clarifications

### Session 2026-10-26

- Q: どの計算の文章問題にする？ → A: たし算・ひき算・かけ算・わり算・あまりのあるわり算のすべて
- Q: 答えの欄に単位をつける？ → A: つける（[ ]こ、[ ]まい、[ ]円 など）
- Q: ひな形の確認は？ → A: 先に一覧（templates.md）を保護者が確認してから作る。確認済み（2026-10-26、変更なし）
- Q: 扱いは？ → 時こく・長さ重さかさと同じ。新しい種類「文章問題」としてレベル1から始め、デイリーチャレンジには出さない

## 問題

- ひな形と難易度は [templates.md](./templates.md) のとおり（ひな形20個、難易度1〜10、各難易度30問）
- あまりのあるわり算の答えは「[ ]こ あまり [ ]こ」「[ ]人 あまり [ ]まい」のように、単位つきの2つの欄。両方合うときだけ正解
- 数字は、文章として自然になる範囲にする（わり切れる、のこりが0より大きい、あまりが1以上 など）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 文章問題を選んで練習する (Priority: P1)

**Independent Test**: 子供でログインし、「文章問題」を選んで問題を解き、単位つきの欄に答えて正しく判定されることを確認する。

**Acceptance Scenarios**:

1. **Given** ホーム画面、**When** 計算の種類を見る、**Then** 「文章問題」が選べ、レベル1と出る
2. **Given** 「赤い 花が 24本、白い 花が 13本 さいています。あわせて 何本 ですか。」、**When** 問題画面を開く、**Then** 文章と「[ ]本」の欄が出て、37 と答えると正解
3. **Given** 「26この あめを 4人で 同じ数ずつ 分けます。…」、**When** 問題画面を開く、**Then** 「[ ]こ あまり [ ]こ」の欄が出て、6・2 と答えると正解、どちらか違えば不正解で「こたえは 6こ あまり 2こ」と出る

### User Story 2 - 学習結果で別に集計される (Priority: P2)

**Acceptance Scenarios**:

1. **Given** 文章問題を解いた、**When** 学習結果を開く、**Then** 種類別の集計・タブ・学習記録の一覧に「文章問題」が出て、答えは「37本」「6こ あまり 2こ」のように単位つき

### Edge Cases

- デイリーチャレンジには選ばない
- 公開済みの DB にも次の起動で問題が追加される（011）。既存の問題・学習記録は変わらない。DB の形は変わらない（マイグレーションなし）

## Requirements _(mandatory)_

- **FR-001**: 計算の種類に「文章問題」を末尾に追加しなければならない
- **FR-002**: 問題は templates.md のひな形と難易度に従って作らなければならない。ひな形以外の文章を出してはならない
- **FR-003**: 答えの欄は単位つき（あまりのあるわり算は「あまり」をはさんだ2つの欄）で、両方合うときだけ正解
- **FR-004**: デイリーチャレンジに選んではならない
- **FR-005**: 計算の種類を表示するすべての画面で「文章問題」と表示しなければならない

## Success Criteria _(mandatory)_

- **SC-001**: 全問題が、ひな形どおりの文章で、正解が正しく、難易度表の条件を満たすことを自動テストで確認できる
- **SC-002**: 既存の問題・学習記録・画面の表示は変わらない
