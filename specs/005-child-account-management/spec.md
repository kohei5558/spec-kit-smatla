# Feature Specification: 子供アカウント管理画面

**Feature Branch**: `005-child-account-management`  
**Created**: 2026年2月7日  
**Status**: Draft  
**Input**: User description: "保護者が子供アカウントを作成・管理する画面を作成します"

## Clarifications

### Session 2026-02-07

- Q: 同一保護者アカウント内で、複数の子供に同じPINコード（例：1234）を設定することについて、どのように扱いますか？ → A: 同一PINは許可するが、「他の子供と同じPINです。セキュリティ上推奨しません」という警告を表示する
- Q: PINコード入力を3回失敗して5分間ロックアウトされた後、どのように解除しますか？ → A: 5分経過後に自動的にロックアウトが解除され、再度PINを入力できるようになる
- Q: 子供ログイン画面で、複数の子供アカウントがある場合、どのように子供を選択しますか？ → A: 各子供のアバター画像と名前が表示されたカード形式の一覧から、タップ/クリックで選択
- Q: アバター画像はどのように提供しますか？ → A: システムが用意した10〜20種類のプリセットアバター画像（動物、キャラクター等）から選択
- Q: 子供がPINを忘れた場合、保護者はどのように対応しますか？ → A: 保護者が管理画面の子供アカウント編集画面で、新しいPINコードを直接設定する

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 保護者が子供アカウントを新規作成する (Priority: P1)

保護者が管理画面から新しい子供アカウントを作成できる。子供の名前、学年、アバター画像、ログイン用のPINコードを設定する。作成後、子供はそのPINコードでログインできるようになる。

**Why this priority**: 子供アカウントがなければ子供がアプリを使用できない。システムの基盤となる機能で、最も優先度が高い。

**Independent Test**: 保護者アカウントでログインし、子供アカウント作成フォームから必要情報を入力し、作成完了後に子供アカウントでログインできることを確認する。

**Acceptance Scenarios**:

1. **Given** 保護者が管理画面にログインしている状態で、**When** 「子供アカウント管理」メニューをクリックする、**Then** 現在登録されている子供一覧と「新規追加」ボタンが表示される
2. **Given** 子供アカウント一覧画面が表示されている状態で、**When** 「新規追加」ボタンをクリックする、**Then** 子供の名前、学年、アバター画像選択、4桁PINコード入力フォームが表示される
3. **Given** 子供アカウント作成フォームが表示されている状態で、**When** 「太郎」、学年「3年生」、アバター選択、PIN「1234」を入力して「作成」をクリックする、**Then** 子供アカウントが作成され、一覧に追加される
4. **Given** 子供アカウントが作成された状態で、**When** ログアウトして子供ログイン画面を開く、**Then** 「太郎」のアバター画像と名前が表示されたカードが表示される
5. **Given** 子供ログイン画面でカードが表示されている状態で、**When** 「太郎」のカードをタップしPIN「1234」を入力する、**Then** 子供用ホーム画面が表示される
6. **Given** 子供アカウント作成フォームで、**When** 既に存在する名前を入力して作成しようとする、**Then** 「同じ名前の子供アカウントが既に存在します」というエラーメッセージが表示される
7. **Given** 子供アカウント作成フォームで、**When** PINコードを3桁以下で入力する、**Then** 「PINコードは4桁で入力してください」というエラーメッセージが表示される

---

### User Story 2 - 保護者が既存の子供アカウント情報を編集する (Priority: P2)

保護者が既存の子供アカウントの情報を編集できる。名前、学年、アバター画像、PINコードを変更可能。変更内容は即座に反映される。

**Why this priority**: 子供の成長や誤入力の修正に必要。P1の作成機能があれば基本的な運用は可能だが、長期的な利用には編集機能が不可欠。

**Independent Test**: 既存の子供アカウントを選択して編集フォームから情報を変更し、保存後に変更が反映されていることを確認する。

**Acceptance Scenarios**:

1. **Given** 子供アカウント一覧が表示されている状態で、**When** 特定の子供アカウントの「編集」ボタンをクリックする、**Then** その子供の現在の情報（名前、学年、アバター、PIN）が入力された編集フォームが表示される
2. **Given** 子供アカウント編集フォームが表示されている状態で、**When** 学年を「3年生」から「4年生」に変更して「保存」をクリックする、**Then** 変更が保存され、一覧画面に戻り、学年が更新されている
3. **Given** 子供アカウント編集フォームが表示されている状態で、**When** PINコードを変更して保存する、**Then** 次回ログイン時に新しいPINコードでログインが必要になる（子供がPINを忘れた場合にも同じ手順でリセット可能）
4. **Given** 子供アカウント編集フォームが表示されている状態で、**When** アバター画像を変更して保存する、**Then** 子供ログイン画面とホーム画面で新しいアバターが表示される
5. **Given** 子供アカウント編集フォームで、**When** 名前を空欄にして保存しようとする、**Then** 「名前は必須です」というエラーメッセージが表示される

---

### User Story 3 - 保護者が子供の学習状況を確認する (Priority: P2)

保護者が各子供アカウントの詳細画面で、現在の学習状況（総問題数、正答率、獲得ポイント、最終学習日、連続学習日数）を確認できる。

**Why this priority**: 保護者が子供の学習進捗を把握し、適切なサポートを提供するために重要。ただし、アカウント作成・編集ができれば基本運用は可能。

**Independent Test**: 子供アカウント詳細画面から学習統計データを取得し、視覚的に表示することを確認する。

**Acceptance Scenarios**:

1. **Given** 子供アカウント一覧が表示されている状態で、**When** 特定の子供の「詳細」ボタンをクリックする、**Then** その子供の基本情報と学習状況サマリーが表示される
2. **Given** 子供アカウント詳細画面が表示されている状態で、**When** 学習状況セクションを確認する、**Then** 総問題数、正答率（%）、獲得ポイント、最終学習日、連続学習日数が表示される
3. **Given** 子供が過去7日間に問題を解いている状態で、**When** 詳細画面を開く、**Then** 過去7日間の学習アクティビティがグラフで表示される
4. **Given** 子供が一度も学習していない状態で、**When** 詳細画面を開く、**Then** 「まだ学習記録がありません」というメッセージが表示される

---

### User Story 4 - 保護者が子供アカウントを一時停止する (Priority: P3)

保護者が子供アカウントを一時停止できる。停止中の子供アカウントはログインできなくなる。再度有効化することで復帰可能。

**Why this priority**: 行儀が悪い時の制限措置や、一時的な使用禁止に有用。ただし、完全削除ではなく一時的な措置なので優先度は低い。

**Independent Test**: 子供アカウントを停止状態に変更し、その子供がログインできないことを確認し、再有効化後にログインできることを確認する。

**Acceptance Scenarios**:

1. **Given** 子供アカウント一覧が表示されている状態で、**When** 特定の子供の「停止」ボタンをクリックする、**Then** 確認ダイアログが表示され、「停止する」を選択するとステータスが「停止中」になる
2. **Given** 子供アカウントが停止中の状態で、**When** その子供がログインしようとする、**Then** 「このアカウントは現在使用できません。保護者に相談してください」というメッセージが表示される
3. **Given** 停止中の子供アカウント一覧が表示されている状態で、**When** 「再開」ボタンをクリックする、**Then** ステータスが「有効」に戻り、子供が再びログインできるようになる

---

### User Story 5 - 保護者が子供アカウントを削除する (Priority: P3)

保護者が子供アカウントを完全削除できる。削除前に確認メッセージが表示され、削除後は全ての学習データも削除される。

**Why this priority**: 誤って作成した場合や、子供がアプリを使用しなくなった場合に必要。頻度は低いが、データ管理上必要な機能。

**Independent Test**: 子供アカウントを削除し、データベースから該当レコードと関連する学習データが削除されることを確認する。

**Acceptance Scenarios**:

1. **Given** 子供アカウント一覧が表示されている状態で、**When** 特定の子供の「削除」ボタンをクリックする、**Then** 「本当に削除しますか？学習データも全て削除されます」という警告メッセージが表示される
2. **Given** 削除確認ダイアログが表示されている状態で、**When** 「削除する」を選択する、**Then** 子供アカウントと関連する学習データが削除され、一覧から消える
3. **Given** 削除確認ダイアログが表示されている状態で、**When** 「キャンセル」を選択する、**Then** 削除されず、一覧画面に戻る
4. **Given** 子供アカウントが削除された状態で、**When** その子供のPINでログインしようとする、**Then** 「アカウントが見つかりません」というエラーメッセージが表示される

---

### Edge Cases

- 保護者が複数の子供に同じPINコードを設定する場合、システムは警告メッセージ「他の子供と同じPINです。セキュリティ上推奨しません」を表示するが、設定は許可する
- PINコード入力を3回連続で失敗すると5分間ロックアウトされ、5分経過後に自動的に解除される。保護者の手動介入は不要
- 子供アカウントの上限数は設定するか？（家庭に5人以上の子供がいる可能性を考慮）
- 子供がPINを忘れた場合、保護者は管理画面の子供アカウント編集画面で新しいPINコードを直接設定する。追加の認証やリセットフローは不要
- 保護者アカウントが複数存在する場合、どの保護者が子供アカウントを管理するか？（現状は1家庭1保護者アカウント前提）
- 削除された子供の学習データを復元できるか？（完全削除とし、復元不可。削除前に十分な警告を表示）
- 停止中の子供アカウントでも過去の学習データは保持されるか？（はい、停止は一時的なログイン制限のみ）
- 子供アカウント作成時にアバター画像を選択しなかった場合、システムはデフォルトアバター（プリセットの1つ）を自動設定する
- アバター画像はシステムが用意した10〜20種類のプリセット（動物、キャラクター等）から選択する。カスタム画像のアップロードは不可
- 学年の選択肢は小学1年生から6年生までか？（はい、小学生対象アプリのため1〜6年生を選択肢として提供）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 保護者は子供の名前、学年（1〜6年生）、アバター画像（システム提供のプリセットから選択）、4桁PINコードを入力して新しい子供アカウントを作成できなければならない
- **FR-002**: システムは子供アカウント作成時に、名前とPINコードの入力必須バリデーションを実施しなければならない
- **FR-003**: システムは同一保護者アカウント内で重複する子供の名前を許可しない（エラーメッセージを表示）
- **FR-004**: システムはPINコードが4桁の数字であることを検証しなければならない
- **FR-004-A**: システムは同一保護者アカウント内で複数の子供が同じPINコードを設定する場合、警告メッセージ「他の子供と同じPINです。セキュリティ上推奨しません」を表示するが、設定は許可しなければならない
- **FR-005**: 子供はログイン画面で、アバター画像と名前が表示されたカード形式の一覧から自分を選択し、PINコードを入力してログインできなければならない
- **FR-006**: 保護者は既存の子供アカウントの名前、学年、アバター、PINコードを編集できなければならない
- **FR-007**: システムは子供アカウント編集時に変更内容を即座にデータベースに反映しなければならない
- **FR-008**: 保護者は各子供アカウントの詳細画面で、総問題数、正答率、獲得ポイント、最終学習日、連続学習日数を確認できなければならない
- **FR-009**: システムは子供の学習統計データを集計し、保護者に視覚的に表示できなければならない
- **FR-010**: 保護者は子供アカウントを一時停止でき、停止中の子供はログインできなくなる
- **FR-011**: 保護者は停止中の子供アカウントを再開でき、再開後は子供が再びログインできるようになる
- **FR-012**: 保護者は子供アカウントを削除でき、削除時に確認ダイアログを表示しなければならない
- **FR-013**: システムは子供アカウント削除時に、関連する全ての学習データ（学習履歴、ポイント、交換申請履歴）も削除しなければならない
- **FR-014**: システムは10〜20種類のプリセットアバター画像（動物、キャラクター等）を提供し、子供アカウント作成時にアバターが未選択の場合、デフォルトアバターを自動設定しなければならない
- **FR-015**: システムは保護者が作成できる子供アカウント数の上限を10アカウントに設定しなければならない

### Key Entities

- **子供アカウント**: 保護者が管理する子供の情報を保持。名前、学年（1〜6年生）、アバター画像ID（プリセットアバターの識別子）、PINコード（暗号化保存）、ステータス（有効/停止）、作成日時、最終更新日時、保護者アカウントIDとの紐付けを含む
- **学習統計サマリー**: 子供アカウントごとの集計データ。総問題数、正答数、不正解数、正答率、獲得ポイント総数、最終学習日時、連続学習日数を含む
- **保護者アカウント**: 複数の子供アカウントを管理する親アカウント。メールアドレス、パスワード（ハッシュ化）、作成日時を含む

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 保護者が子供アカウントを作成する操作を3分以内に完了できる（名前、学年、アバター、PIN設定）
- **SC-002**: システムは10件の子供アカウントを同時に管理でき、一覧表示の読み込み時間が1秒以内である
- **SC-003**: 子供アカウント編集後、変更内容が即座（1秒以内）に反映され、次回ログイン時に適用される
- **SC-004**: 保護者の90%が子供の学習状況サマリー（正答率、ポイント、学習日数）を初見で理解できる
- **SC-005**: 子供アカウント削除操作後、関連する全ての学習データが完全に削除され、データベースに残存しない
- **SC-006**: 停止中の子供アカウントのログイン試行時、子供にわかりやすいエラーメッセージが表示され、サポート問い合わせが発生しない
- **SC-007**: PINコード入力エラー時、3回失敗後に5分間のロックアウト機能が作動し、5分経過後に自動解除される。不正アクセスを防止しつつ、保護者の介入なしで子供が再試行できる
